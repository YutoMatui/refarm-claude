# リーダー会準備スキル

今週のリーダー報告会ページを中央議事録DBに作成し、各チームのセクションをNotionの記録から自動で埋める。
ゴールは「リーダー会が始まった瞬間に議題が揃っている」状態。記入待ち・口頭ヒアリングをなくす。

**AI自走の原則**: 実行中にユーザーへ質問して止まらない。情報がなければ「記録なし」と明示して先へ進む。

## 引数

$ARGUMENTS

空の場合は直近の火曜日（今日が火曜なら今日、月曜なら翌日）を開催日とする。日付指定があればその日付で作成する。

## 現在のチーム構成（これが正。旧名称は使わない）

セクションは必ずこの4チーム構成で作る:
1. **スープチーム**（旧: すりながしチーム — 旧名は使わない）
2. **消費者チーム（おかえり農園）**
3. **クリエイティブチーム**
4. **バックオフィスチーム**

※ **アグリチームは解体済み（2026/07時点）**。業務はスープチームに合流したため、セクションを作成しない。アグリ関連の記録があってもスープチームの中に統合する。

## 手順

### 1. 開催日と対象期間の確定
**リーダー報告会は毎週火曜の夜に開催する。ページは前日（月曜）までに完成させておく**（会が始まった瞬間に議題が揃っている状態を作るため、当日朝や開始直前に作らない）。

- 開催日 = 直近の火曜日
- 対象期間 = 前回開催日（前週火曜）〜作成日（通常は月曜）

作成日が月曜なので、**火曜当日の活動は対象期間に入らない**。前週火曜のリーダー会以降に起きたことを拾う、と考えればよい。

### 2. 既存ページの確認（重複・旧バージョンのチェック必須）
中央議事録DB `collection://30591268-b898-803c-b2f0-000b13fb9581` を `notion-search` で当日の「リーダー報告会」で検索し、**同日付のページが複数ないか必ず確認する**（誰かが前週のページを手動複製して作った旧フォーマット版が紛れ込むことがある）。

- ページが1件もない → 新規作成（ミーティング名=`YYYY/MM/DD リーダー報告会`、日付=開催日、チーム=定例）
- ページが1件だけ → そのページを更新
- **ページが複数ある場合**: 現行のチーム構成で書かれている方を正式ページとして扱い、そちらを更新する。旧チーム名（消費者チーム(ToC)/飲食店チーム/すりながしチーム/アグリパートナーチーム/カスタマーリレーションチームなど）が残っているページを見つけたら、**削除はせず**その場で現行構成に書き換え（旧チーム名セクションのリネーム、廃止チーム・解体済みチームのセクション削除）、ページ冒頭に「⚠️このページは重複／正式版は◯◯を参照」の一文を追記する。旧バージョンを放置したまま新しい正式ページだけ作る、ということをしない。

旧バージョンが今後も自然発生する場合（誰かが前週ページを複製している可能性が高い）、実行結果の報告でその旨をユーザーに明示し、複製元を絶つよう促す。

**既にページ内にユーザーが手動で書き込んだ内容（実際の会議メモ・回答済みの質問など）がある場合は絶対に上書きしない。** 自動生成部分（未記入のプレースホルダーや古い自動生成テキスト）だけを更新対象にする。

### 3. 各チームの週次情報を収集
`/weekly-team-report` と同じソース（同スキルの「情報ソース」表を参照）から各チームの今週の活動・困りごと・次週予定を抽出する。既に今週の週次まとめページが作成済みならそれを優先的に使う。

**チームからリーダー会や代表宛の質問・相談・確認事項が見つかった場合は、「全体に向けて話したいこと」ではなく、その質問を出したチーム自身の「困っていること」に書く。** 「全体に向けて話したいこと」には、特定のチームに属さない真に全社（全チーム）共通の議題だけを書く（例: 部費制度、代表引継ぎのスケジュール、資金体制など）。

### 4. 引継ぎ状況の確認
引継ぎ検討ページ `37391268-b898-81d0-8b88-d5e7e8bae088` の内容は表に書き起こさず、**そのページへのリンクを貼るだけ**にする（ページ側の更新が反映されず情報が古くなるのを防ぐため）。

### 5. 経費申請・予算ステータスの集計
💰 経費申請・予算管理DB `collection://19a0438e-9793-4949-8e69-1e1ebecbc3ed` をチームごとに集計し、ステータス別件数（申請中／承認／却下／実費記録済み／精算完了）と予定金額・実費金額の合計をチームごとの表にする。個別の申請内容は書き起こさず、件数・金額の集計のみ。DBへのリンクも添える。

運用フロー（メンバーが申請 → チームリーダーが承認 → 実費記録 → バックオフィスがやよいへ入力）自体はこのDBの説明文に書いてあるので、ここでは触れなくてよい。

## 注意事項
- 事実ベース。記録にないことを推測で埋めない
- 各チームが手で追記した内容は上書きしない（自動生成部分の更新のみ）
- チームの質問・相談は「困っていること」に集約する。「全体に向けて話したいこと」を各チームの質問置き場にしない

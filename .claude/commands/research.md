# 調査スキル（/research）

スープ事業・おかえり農園などの調査タスクを、**過去調査の重複チェック → 多角的な情報収集 → 意思決定につながるレポート**の型で実行する。

**AI自走の原則**: 実行中にユーザーへ質問して止まらない。調査範囲が曖昧なら妥当な解釈を宣言して進め、レポート冒頭に「本調査のスコープ」として明記する。

## 引数

$ARGUMENTS

調査テーマを自由文で受け取る（例:「三宮のスープ競合」「ECG周辺1.2km圏のオフィス拠点候補」「サイド用パンの調達先候補」「西区で高齢者が集まる場所」）。

## 想定される調査タイプと観点

| タイプ | 例 | 必須観点 |
|---|---|---|
| 競合調査 | スープ店・惣菜・デリバリー | 価格帯・メニュー・チャネル・顧客ジョブ（誰のどんな用途か）・りふぁーむとの差分。※ベリーベリースープは分析済み（惣菜ジョブでシーンが違う、Notion参照） |
| 市場分析 | スープ市場・健康食・CSA | 市場規模の根拠（出典必須）・トレンド・神戸ローカルへの換算 |
| 拠点・立地調査 | オフィス/コワーキング/クリニック/士業 | ECG（加納町3-11-8）起点・半径1.2km圏内が配達圏。従業員規模・昼食動線・受付形態。既存ロングリスト51拠点と重複しないか確認 |
| 調達先調査 | パン屋・食材・容器 | 卸対応可否・ロット・価格・アレルゲン（乳・卵の有無はスープ事業の制約に直結）・配達/引取 |
| シニア調査（おかえり農園） | 高齢者が集まる場所・チャネル | 西区中心。いきいきサロン・老人クラブ・地域包括・公民館・プール等の施設。行政チャネル（後援・広報誌・回覧板）との接続。既存調査『高齢者コミュニティの成功/失敗要因』と重複しないか確認 |

## 手順

### 1. 過去調査の重複チェック（必ず最初に）
Notionを検索し、同テーマの既存調査がないか確認する:
- スープ関連: 📂 05 調査・データ（`39291268-b898-8191-b965-ffb285d63dee`）
- おかえり農園関連: 競合調査マップ・高齢者コミュニティ調査等（「おかえり農園」「シニア」で検索）
既存調査がある場合は**ゼロからやり直さず差分・更新に絞る**。レポートに既存調査へのリンクを張る。

### 2. 調査計画
テーマを3〜5個の調査観点（角度）に分解して宣言する。大きなテーマの場合は観点ごとにサブエージェント（general-purpose）に分担させてよい。

### 3. 情報収集
- **WebSearch/WebFetch** を主力にする。一次情報（公式サイト・行政資料・統計）を優先し、まとめ記事は裏取りに使う
- 統計は e-Stat・神戸市統計・国勢調査（小地域）・商業統計等の公的データを優先
- 店舗・施設調査は 公式サイト＋Googleマップ情報（営業時間・レビュー傾向）＋食べログ等を突合
- **各事実に出典URLと確認日を必ず記録する**。見つからなかったことも「確認できず」と正直に書く

### 4. りふぁーむ文脈への接続
収集した事実を、必ず自社の意思決定に翻訳する:
- スープ: 獲得軸=健康・手軽／継続軸=地域応援。量はデリバリー、間借りは目的地。単品650円・朝ベジ会員（¥2,200/¥4,000）との比較で見る
- おかえり農園: 継続の本質は「居場所」。役割・貢献の可視化が差別化。シーズン24,000円（≒月4,000円・プール並み）の価格感で見る
- 消費者ニーズは課題解決型でなく**欲望充足型（自己都合の「気になり」起点）**で解釈する

### 5. レポート作成（Notion）
作成先:
- スープ関連 → 📂 05 調査・データ（`39291268-b898-8191-b965-ffb285d63dee`）の配下
- おかえり農園関連 → 実行たたき台等の関連ページと同じ階層に「【調査まとめ】〜」として作成
- タイトルは `【調査】{テーマ}（YYYY-MM-DD）`

構成（結論ファースト）:
```
> 🎯 結論（So What）: 3行以内。「だから何をすべきか」まで書く

## 本調査のスコープ（自分で解釈した範囲を明記）
## 事実（観点別。テーブル中心・出典と確認日付き）
## 示唆（りふぁーむにとっての意味）
## 推奨アクション（担当を置けるレベルの粒度・優先度付き）
## 既存調査との関係（リンク）
## 出典一覧
```

### 6. 実行結果の報告
作成したNotionページのURLと結論3行を出力して終了する。

## 注意事項
- 推測と事実を混ぜない。推測は「仮説」と明示する
- 数字には必ず出典を付ける。出典のない市場規模は書かない
- 調査のための調査にしない。「推奨アクション」が書けない調査は観点を再設計する
- Notionの構造ルールに従う（スープ直下に新規ページを作らない・古い調査は上書きせず差分ページ）

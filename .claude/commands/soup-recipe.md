# スープメニュー開発スキル（/soup-recipe）

丸ごと野菜スープの新メニューを、soup-appの栄養設計システムと**完全に同じデータ・同じ計算**で開発する。
Claude Code内で完結するため追加API費用はゼロ（アプリ内のAIレシピボタンはチーム用・従量課金）。

## 引数

$ARGUMENTS

引数＝開発のお題（例:「9月のかぼちゃメニュー」「貧血気味の人向け」「冷製でさっぱり」）。
空の場合は「どんなスープを開発しますか？（主役食材・季節・ターゲットの悩みなど）」と確認する。

## 必ず守る制約（事業の前提）

1. **ベースは肉不使用（植物性）**。たんぱく質は枝豆・豆腐・厚揚げ・高野豆腐・蒸し大豆など植物性で補う。肉はトッピングオプション（蒸し鶏）のみ（2026-07-12解禁）
2. **乳製品・バター不使用**。コクは豆乳・出汁・白味噌・すりごま・オリーブ油で
3. **和出汁ベース**。旨味の相乗（グルタミン酸×イノシン酸）を設計に使う
4. **仕込みも提供も三宮の間借り厨房（ECG）のみ。レンタルキッチンは使わない（2026-07-12決定）**。オーブン工程は原則コンロ代替（フライパン焼き付け＋蓋蒸し等）を主手順にする
5. **1杯250〜300ml**（朝1分で飲み切れる量。栄養を盛ると増えがちなので出汁・豆乳を絞って調整）
6. **塩分濃度0.5%前後**（`SALT_RULE`：下限0.4%・上限0.65%）。検証スクリプトで必ず確認する
7. 旬・地元優先：8月の神戸市西区＝トマト・とうもろこし・枝豆・なす・オクラ・ピーマン/パプリカ・きゅうり・モロヘイヤ・つるむらさき・ゴーヤ・ズッキーニ・かぼちゃ（走り）・みょうが・大葉。9月以降はかぼちゃ・さつまいも・根菜へ

## 試作で判明した「現実と味の乖離」の学び（2026-07-05 実試食・必ず反映）

数字上合格でも味が成立しないパターンが実試食で判明した。レシピ設計時は以下を必ず守る：

1. **塩分濃度が最重要**。「物足りない」「だし感がない」の主因は塩分不足だった（旧レシピは0.23〜0.28%しかなかった）。目標0.5%前後。塩が決まると出汁の香りが立つ。工程には必ず「**3カップ当て比べ**（塩±0.5g/杯で3段階を並べて試飲）」を入れる
2. **繊維質（とうもろこしの皮・芯・ひげ、野菜の固い部分）はミキサーにかけない**。出汁採り（15分煮出し→こす）にとどめる。フードプロセッサーにかけると繊維が残り「飲みにくい」になる
3. **なめらか化＝高出力ミキサー（800W級）＋シノワ/細かめストレーナーで裏ごし**。フードプロセッサーは「刻む」道具でポタージュには不向き（枝豆の口当たり問題の主因）。枝豆は薄皮を除くと更に良い
4. **生トマトは青臭く甘みが出ない**。ロースト必須（丸ごとアルミ包み200℃60分）。玉ねぎは皮ごとロースト。酸味が残る場合は甘味料を足さず**更に煮る**（酸の角が取れる）
5. **玉ねぎは甘み・コクの土台としてほぼ全レシピに入れる**（弱火10分炒め or ロースト）
6. **とろみはポタージュ寄り**（スプーンの背に薄く膜が残る）。サラサラだと「丸ごと使っている感」が出ない。緩ければ水を足さず煮詰める
7. **全部こすレシピは「具ゼロ」になる**。トッピング（焼きコーン・焼き枝豆・もち麦・刻みオクラ等の「見える具」）を必ずセットで設計し、提供時に上に乗せる（底に沈めない）
8. **工程には試飲チェックポイントを明記する**（塩→とろみ→香りの順）。「計算上正しい」と「おいしい」の差は試飲でしか埋まらない

## 手順

### 1. データソースを読む
`../soup-app/client/src/data/nutrition.js`（soup-appリポジトリをこのリポジトリの隣にcloneしておく。無ければ「soup-app未取得のため概算」と明示して八訂概算で進める）を必ずReadする。ここにある食材マスタ（八訂概算・アレルゲン付き）・1食基準（表示基準値÷3）・合格ライン・調理ロス係数が唯一の正。マスタにない食材を使う場合は八訂の値を調べてマスタへの追加も提案する。

### 2. レシピを組み、実データで検証する
食材と1杯あたりグラムを決めたら、**必ず以下のNodeスクリプトで実計算**する（アプリと同じ関数を使うため手計算より確実）。`rows` を書き換えて実行：

```bash
node -e "import('file:///$(pwd)/../soup-app/client/src/data/nutrition.js').then(m=>{const byId=Object.fromEntries(m.FOODS.map(f=>[f.id,f]));const rows=[{foodId:'tomato',grams:135},{foodId:'edamame',grams:35}];const t=m.computeNutrition(rows,byId,{cookLoss:true});const j=m.judgePass(t);const a=m.collectAllergens(rows,byId);const pct=k=>Math.round(t[k]/m.NUTRIENTS.find(n=>n.key===k).perMeal*100);console.log(JSON.stringify({容量ml:Math.round(m.estimateVolumeMl(rows)),野菜g:Math.round(t.vegGrams),たんぱく質g:+t.protein.toFixed(1),合格:j.pass,基準30pc超え:j.overNutrients.map(n=>n.label),食塩g:+t.salt.toFixed(2),アレルゲン:a.items,参考:a.notes},null,1))})"
```

**合格ライン**：野菜120g以上 かつ 1食基準30%以上の栄養素3つ以上。**容量**：250〜300ml。**食塩**：2.3g以下。
不合格・容量オーバーなら食材を調整して再計算を繰り返す（出汁を絞る／緑黄色野菜・豆を足す）。

### 3. 出力フォーマット
1. **一言コンセプト**（獲得軸=健康×手軽の言葉で）
2. **材料**（1杯分と10杯仕込みの両方・グラム明記）
3. **工程**（番号つき・プロの勘所を一言ずつ。仕込み8割/現地2割で分ける）
4. **栄養検証表**（スクリプトの実測値。合格判定・容量・アレルゲンを明記）
5. **表示シール文面**（品名/原材料重量順/アレルゲン28品目/栄養成分表示5項目/「本日中にお召し上がりください」/推定値注記）
6. **盛り付け・ビジュアル**と**味変・トッピング**（悩み別推薦と整合）

### 4. 確定したらプリセット登録を提案
レシピが固まったら `PRESET_RECIPES` への追加をユーザーに提案し、承認されたら `nutrition.js` を編集（コミット・pushは指示があった場合のみ）。

## 責任ある表現のルール（厳守）

- 成分値は八訂の**推定値**。POP等の対外表示は「推定値」と明記し、最終版は**管理栄養士等のレビュー**を推奨する（未レビューのまま断定表現にしない）
- 「◯◯に効く」「改善する」等の**効能表現はNG**。「1日の◯%がとれる」の事実表現のみ
- アレルゲンは義務8品目と推奨20品目を区別し、レシピ変更時は必ず再集計する

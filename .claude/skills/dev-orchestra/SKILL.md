# オーケストラ開発（汎用・全プロジェクト共通）

役割：**指揮官（fable/opus）＝設計とレビュー、実行部隊（sonnet）＝実装**。
品質は実行モデルの能力ではなく「**スペックの粒度**」と「**指揮官のレビュー**」で担保する。
目標品質＝指揮官が自分で書いた場合と同等。

## 全体フロー

```
指揮官: 事前調査（外部仕様を自分で確認）→ スペック執筆
   ↓ Agentツールでディスパッチ（sonnet・必要なら並行）
実行部隊: Read→実装→自己検証（全通しまで）→ 差分報告（commit禁止）
   ↓ 完了通知
指揮官: git diff全行レビュー → 検証を自分で再実行 → 軽微修正は直接／構造問題は差し戻し
   ↓
指揮官: コミット・push・ユーザー報告
```

## 1. スペックの書き方（品質の9割はここ）

曖昧さを残さない。テンプレ：

```
# スペック: <機能名>
## 背景（1-3行）
## 作業ディレクトリ・リポジトリ
## 変更ファイル（厳密なフルパス・新規/修正の別。「これ以外は変更禁止」と明記）
## 参照すべき既存パターン（ファイルパス＋何を真似るか）
## 実装詳細
   - データ構造・関数名・エンドポイント・UI文言まで具体的に
   - 迷いそうな箇所は完成コード断片を貼る
   - 外部仕様（既存関数のシグネチャ・DB列・価格計算式等）は指揮官が事前にコードを読んで確認し、書き写す
## 確認せよ（実行部隊がコードを読んで検証すべき前提。結果を報告させる）
## やらないこと（スコープ外の明記）
## 受け入れ基準（チェックリスト）
## 検証コマンド（コピペで実行できる形。プロジェクト付録から転記）
```

## 2. ディスパッチ

- Agentツール：`subagent_type: "impl-exec"`（未登録セッションでは `general-purpose` + `model: "sonnet"`）。長時間タスクは `run_in_background: true`
- スペック全文をプロンプトに貼る（ファイル参照だけにしない）＋実行部隊の絶対ルール（下記）も冒頭に貼る
- **並行時は各スペックの変更ファイル集合を互いに素に**する（共有ファイルは片方だけに割り当て）。並行相手が触るファイルを「触るな」と明記する

実行部隊の絶対ルール（プロンプト冒頭に毎回貼る）：
1. スペックに書かれたことだけを実装（機能追加・リファクタ禁止。気づきは報告へ）
2. 編集前に必ずRead。既存スタイル（日本語コメント・命名・UIクラス）に完全に合わせる
3. git commit / push 禁止
4. 検証コマンド全通しまで直す
5. 報告＝①変更ファイル②「確認せよ」の結果③検証の実際の出力④気づき

## 3. 指揮官の品質ゲート（省略禁止）

1. `git diff` を**全行**レビュー（逸脱・スタイル・業務ルール整合・既存機能の破壊・エラー時フォールバック）
2. 検証コマンドを**指揮官自身が再実行**（報告を鵜呑みにしない）
3. 機能の実測チェック（計算ロジックはnodeやpythonで境界値を叩く）
4. 軽微な問題→指揮官が直接修正／構造的な問題→スペックを直して差し戻し
5. コミット・push・ユーザー報告は指揮官のみ

## 4. プロジェクト付録（検証コマンド・前提）

### soup-app（React+Vite / FastAPI）
```bash
cd ../soup-app/client && npm run build
node -e "import('file:///$(pwd)/../soup-app/client/src/data/nutrition.js').then(m=>console.log(m.PRESET_RECIPES.length))"
# app.mainはローカルでstripe/psycopg未導入のためimport不可。ルーター単体で：
cd ../soup-app/api && DATABASE_URL="sqlite:///:memory:" python -c "from app.routers import <名前>"
```
前提：栄養の正=nutrition.js（原則読み取り専用）／管理UI=adm-*クラス／消費者UI=screen系クラス／塩分0.5%・ベース植物性（肉はトッピングオプションのみ）・1食基準。仕込み場所は三宮の間借り厨房のみ（レンタルキッチン不可）。

### refarm-hp（Next.js 15 + Tailwind）
```bash
cd ../refarm-hp && npm run build
```
前提：コンテンツはcontent/配下のmd/json。SoupIngredientMap等のclientコンポーネントは"use client"。

### okaeri-noen
```bash
cd ../okaeri-noen/client && npm run build
```

（新プロジェクトで使うときは、この付録に検証コマンドと前提を追記してから回すこと）

# 様式③ お知らせ（速いカット）— 閉店・オープン・大事な告知

2026-10-31「11月閉店動画」で、ゆうとに3回直されて決まった型。
第1版は「論外」、第2版は「短すぎ」と言われ、第3版で「いい感じ」になった。
例＝`video/heiten_reel/`（`montage.json`・`make_plan_v3.py`・`plan_v3.json`）、
完成例＝Drive「50日企画素材/完成動画/11月閉店動画_仮v3.mp4」。

**使う動画**：見た人に「行こう」と思ってもらう告知（閉店・オープン・期間限定・イベント出店）。
**使わない動画**：メニューの味や作り方をじっくり見せる動画（→ restaurant）、代表の語りで進める連載（→ pop）。

## 1. 形

- plan.json は `"style": "pop"`、`"no_op_ed": true`、`"mute_clips": true`。カット間のディゾルブ（`transition`）は付けない
- 全体で30〜40秒。1つの文＝1セグメント。セグメントの背景は `scripts/montage.py` で作る（下の 4.）
- 最初の3秒で一番大事な事実を出す（例：「三宮のスープ屋さん VEGEONE は／11月26日で／閉店します」）
- 終わりは「来てほしい日時」→「来てください」→アカウント名の順。日付・時間は1画面に大きく

## 2. カットの長さ（いちばん直された所）

| 長さ | 評価 |
|---|---|
| 写真を2〜3秒、ゆっくり寄るだけ | 「遅くて見てられない・ダサい」 |
| 0.45秒ずつ | 「さすがに短すぎ」 |
| **約1秒（0.9〜1.5秒）** | 採用 |

- 1つの文の間に、約1秒のカットを3〜5本つなぐ。人の動き（お辞儀・手を振る）は1本で2〜3秒見せてよい
- 似た映像を続けない。本数を増やすより、文に合う画を選ぶ

## 3. 素材の選び方（文と画を合わせる）

**言っていることと映像を必ず合わせる。** ゆうとが一番気にするのはここ。採用された組み合わせ：

| 文 | 映像 |
|---|---|
| 11月26日で閉店します | 店員のお辞儀 |
| 8月20日にオープンして | のぼりを立てた外観 → 「2F」看板の入口 → 店内で両手を振って迎える |
| あっという間の3か月 | これまでのスープの実物写真 |
| たくさんのご来店ありがとうございました | トッピング → 注ぐ → 席にスープが届く |
| 毎日たのしく営業できました | 店で実際に盛り付けている手元 → 笑顔 → 手でハート |
| でも、これで終わりではありません | カウンターの奥で立って笑顔 |
| これからはマルシェやイベントで | イベント出店のテントのメンバー写真（横に流す） |
| お店で食べられるのはあと◯日 | 今のメニューの写真 → トレーにのったスープ |
| 最後に食べにきてください | 店の前で手を振る |

**使わないもの（言われたもの）**
- 文と関係のない画（例：「閉店します」に席を案内する手）
- 店から出てきてガッツポーズ（`imo_reel` の 03b）
- 別のイベントの写真（商大祭の写真のうち、カレーの時のもの）
- やめたメンバーが写っている写真（マルシェの集合写真）。**人が写る写真は、今いるメンバーか確かめる**
- 自宅の試作キッチンの映像を「店の営業」に使う
- 赤・黒のベタ背景のカード（「怖い」）。文字は必ず実物の写真か映像の上に置く
- ぼかした背景の上に写真を小さく置く（古く見える）。写真は画面いっぱい、横長は横に流す

## 4. 背景動画の作り方（`scripts/montage.py`）

```bash
python scripts/montage.py video/〈企画名〉/montage.json        # 全部
python scripts/montage.py video/〈企画名〉/montage.json 02 07  # 直したものだけ
```

`montage.json` に、セグメントごとのカットの並びを書く（形はスクリプトの先頭に書いてある。実例は `video/heiten_reel/montage.json`）。

- 動画は `{"video": パス, "ss": 始める秒, "t": 長さ}`、写真は `{"photo": パス, "t": 長さ, "move": "push"または"pan", "cx", "cy"}`
- **iPhone の動画は HDR。** `montage.py` は `hdr.py` を通すので自動で色が直る。CapCut に元の MOV を直接入れない（灰色っぽく暗く沈む。「謎のエフェクト・画質が悪い」と言われた原因）
- 画質：lanczos で縮める、crf 12、つなぐときは再圧縮しない。写真の動きは1コマずつ描く（ガタつかない）
- 看板・器・人が端で切れたら `cx`・`cy`（切り取る中心、0〜1）で動かす
- 解像度の低い素材（720p の LINE 経由の動画など）は1秒程度にとどめる

## 5. 文字

- 色は**白だけ**（黒い縁）。金色・クリーム色は明るい背景で読めない
- 1行は短く、大きく。1枚のカードに1行ずつ入れ、行ごとに大きさを決める
  - 大きさ＝ 960 ÷（文字数 × 7.7）を目安に、上限14（数字・英字は0.55文字と数える）
  - 前ふりの小さい行（「三宮のスープ屋さん VEGEONE は」）は 7.5、決めの行は 14
- 縦の位置：基本は y 1150〜1370（顔の下・下から4分の1より上）。主役（スープ・顔）が下にある画は上（y 330〜650）へ逃がす
- 2行目を少し遅らせて出す（0.4〜0.6秒）と、読む順が自然になる
- 実装の例：`video/heiten_reel/make_plan_v3.py` の `card()`（行ごとの大きさと行間を計算して plan.json を書く）

## 6. ナレーションと BGM（CapCut で人が入れる）

- 台本のナレーションは、1文が背景の長さに収まるように書き直して渡す（目安は1秒に7〜8音）。収まらない文は背景を長くする
- BGM は、前半は温かいピアノ、「でも」の切り返しから明るい曲へ。ナレーションが聞こえる音量（20〜30%）
- 効果音は入れない

## 7. 出す前の確認

- [ ] 最初の3秒で一番大事な事実が読める
- [ ] 文と画が合っている（上の表）。写っている人が今のメンバー
- [ ] 文字が顔やスープにかかっていない
- [ ] 暗く・灰色っぽく見える画がない（HDR の変換漏れ）
- [ ] 日付・時間・残り日数が投稿日に合っている（「あと4日」は投稿日で変わる）
- [ ] 最後にアカウント名
